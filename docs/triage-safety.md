# Symptom triage: safety model and limitations

The symptom checker gives **informational guidance only**: a suggested kind of specialist and an urgency level. It does not diagnose, and it is not a substitute for a clinician. Its rules have **not been reviewed by a clinician**. Treat everything below as an engineering safety net, not a clinical protocol.

Code: `mediflow-backend/src/controllers/aiController.ts`. Tests: `aiController.test.ts` (`npm test` in `mediflow-backend`).

## What the safety layer guarantees

- **Emergencies never depend on the model.** Every turn, before OpenAI is called, `hasEmergencyIndicator` checks every patient message against `EMERGENCY_KEYWORDS`. A match returns `urgency: "emergency"` with `mode: "safety"`, and OpenAI is not called.
- **Later answers count.** An emergency mentioned in the second or third answer is caught, not just one in the opening message.
- **Same rules in both paths.** The AI path and the rules-engine fallback share one matcher.
- **Self-care text is fixed.** It is written in code per urgency level and never generated by the model.

## What happens when OpenAI misbehaves

Any problem with the OpenAI call sends that turn to the rules engine, and the patient still gets an answer.

| Failure | Handling | Logged `reason` |
| --- | --- | --- |
| No API key | OpenAI isn't called | `no_api_key` |
| Daily AI limit reached, or the count can't be checked | OpenAI isn't called | `budget_exceeded`, `budget_unavailable` |
| No reply within 8 s, including the body (`OPENAI_TIMEOUT_MS`) | The request is aborted with `AbortController` | `timeout` |
| Connection failure | Caught | `network_error` |
| Non-2xx status | Status is logged | `http_error` + `status` |
| Model refusal | Caught | `refusal` |
| Empty or non-JSON content | Caught | `empty_response`, `invalid_json` |
| Valid JSON with a wrong field (an unknown urgency, say) | **Rejected, not repaired.** Strict `json_schema` output should prevent this, and `parseAgentTurn` checks again | `schema_mismatch` |
| A 4th question after the cap | Rejected | `question_cap_ignored` |

When the rules engine takes over mid-conversation, it ignores answers to OpenAI's questions. It asks its own follow-up, or concludes on the opening symptoms if the 3-question cap is used up.

Each turn writes one JSON log line (`event: "triage_turn"`) with `mode`, `reason`, `status`, `latencyMs`, `questionsAsked` and `done`. It **never includes patient text, user ids or the triage result**, and a test enforces that.

There are no retries. With an 8 s timeout and a fallback that answers instantly, a retry would mostly add latency for the patient.

## How matching works

| Rule | Example |
| --- | --- |
| Whole words, optional plural `s`/`es` | `ear` matches "ears", not "year" or "near" |
| A trailing `*` marks a stem | `vomit*` matches "vomiting"; `can't breath*` matches "can't breathe" |
| A negation cue within 4 words before a term, in the same clause, cancels it | "I don't have chest pain" is not a match |
| Clauses end at `. , ; : ! ?` and at "but", "though", "however", "except" | "No fever but chest pain" is a match |
| Pseudo-negations are ignored | "not sure if it's chest pain" is a match |
| "never" is not a negation cue, on purpose | "I've never had chest pain this bad" is a match |
| Follow-up answers in the fallback are matched as whole words, without negation | "Yes, mostly normal" no longer counts as "no" |

When in doubt the matcher **leans toward over-triage**: wrongly flagging an emergency costs less than missing one.

## Known limitations

1. **The emergency list is short and unvalidated.** It misses, for example, "chest tightness", "chest pressure", "fainted", "passed out", "slurred speech", "face drooping", "coughing up blood", "overdose" and "kill myself". When OpenAI is configured these are left to the model. In the fallback they go through the specialty rules, which can return `low`.
2. **Negation is a heuristic.** It looks at a 4-word window, not grammar. Unusual phrasing can wrongly cancel a symptom or wrongly keep it.
3. **Over-triage from context.** Any affirmed mention counts. "My dad had a heart attack last year" is flagged as an emergency, because family history and past events are not distinguished.
4. **English only, exact spellings.** "Chest pian" and other typos are missed, apart from the few spellings listed in the code.
5. **First matching rule wins.** Specialty rules have no scoring. "My child has a rash" goes to Dermatology, not Pediatrics, because Dermatology is listed first.
6. **Long messages are truncated before checking.** `sanitizeMessages` keeps 500 characters per message and the last 20 messages. Text past that point is never checked.
7. **The client owns the transcript.** Fake assistant turns are accepted. The emergency check only reads patient messages, so it still holds, but question limits and model context can be manipulated.
8. **Model under-triage.** For anything not on the list, urgency is whatever the model returns, checked only against the allowed values.

## Required clinical review

Before real patients use this feature, a qualified clinician should review and sign off:

- [ ] `EMERGENCY_KEYWORDS`: what is missing, and what over-triages
- [ ] Negation cues, pseudo-negations and the 4-word window
- [ ] `RULES`: keyword to specialty mapping, rule order and base urgency
- [ ] `CATEGORY_FOLLOWUPS`: the questions and which answers raise urgency
- [ ] `SELF_CARE_GUIDANCE` and `DISCLAIMER` text
- [ ] The OpenAI system prompt

The test cases in `aiController.test.ts` are the executable form of these rules. Any change to the lists above should come with updated test cases and a fresh clinical review.
